## 12. 移动端

完整内容见 `/design#mobile`（那一页是真源）。核心判断一句话：
**带过去的是品牌，交还给平台的是形制。**

| | |
| --- | --- |
| 跟着品牌走 | 颜色 token · 字阶意图 · 语义与形制约定 · 图标语义名 · 语气 · 空态铁律 |
| 交还给平台 | 导航 · 返回 · 控件形制 · 字体 · 动效曲线 · 触感 · 安全区 |

三条与 Web 不同的：

1. **暗色必须做。** Web 端刻意不做（§9），移动端不行 —— 系统里有那个开关，
   用户切了之后期待 App 跟着变，不跟就是 App 的问题。且不是把浅色反过来：
   深底上 `ink-900` 当主色是看不见的，蓝色也要提亮（`#0052d9` 在 ink-900 上只有 2.1:1）。
2. **命中区取各自平台的值**：Android 48dp、Apple 44pt。不取交集也不取并集 ——
   那是两家人机指南各自算出来的。
3. **三栏骨架不搬过去。** 导航进底部栏，上下文栏收成可上拉的底部面板，返回交给系统。

落地状态（2026-08-31）：
- Android 已接 `ShennaoTheme`（`clients/android/.../Theme.kt`），根上一换，
  App 里 43 处 `MaterialTheme.colorScheme.*` 自动拿到深脑的值，屏幕代码零改动。
  **本机没有 JDK，这份 Kotlin 未经编译验证** —— API 名对着 compose-bom 2024.06 静态核过，仅此而已。
- macOS 的 `DeepBrainRecorder` 是录音工具（60 个 Swift 里只有 1 个 SwiftUI），暂无成规模界面。
- iOS 尚不存在，Apple 侧是给它开工时用的。

## 13. 图标跨端

完整内容见 `/design#iconmulti`。核心是先看清 **67 个语义名里混着两种东西**：

| | 数量 | 策略 |
| --- | --- | --- |
| 通用动作（搜索 · 播放 · 关闭…） | 44 | **交给平台**。各端有成套图形，用户对形状有肌肉记忆 |
| 深脑产品概念（矛盾 · 原则 · 待解 · 下文…） | 23 | **必须自带**。任何平台的图标库里都没有 |

两者的适配策略正好相反，混在一起谈就谈不清楚。

- **语义名是跨端契约，图形是各端实现。** 四端同名，翻译文案、写测试、排查问题时说同一种语言。
- **产品概念图形四端应尽量一致**（用户在网页认得的「矛盾」到手机上得还认得）；
  **通用动作正相反，越像平台原生越好**。

各端要当心的：

| 端 | 当心 |
| --- | --- |
| Android | Material Symbols 默认比 lucide 的 1.5 粗，产品概念要跟着调到同一档 —— **宁可端内一致，不要端间一致** |
| Apple | SF Symbols 跟随字重与 Dynamic Type 缩放。自带图标若只是普通图片，一行里会跟文字对不齐，**必须做成 symbol** |
| 小程序 | **主包 2MB 是硬顶**，67 个全塞进去会挤掉业务代码。常用的内联，其余分包懒加载 |
| Pad | 不是新的一套图标，是**尺寸档与命中区**的问题 |

落地：23 个产品概念已导出为平台无关 SVG 真源（`packages/ui/icons/`），
由 `scripts/export-brand-icons.mjs` 生成 —— 渲染真实组件而非读图标库内部数据，
规格由 `packages/ui/src/brand-icons.test.ts` 钉住（24×24 · 1.5 · currentColor · 不许内嵌颜色）。
