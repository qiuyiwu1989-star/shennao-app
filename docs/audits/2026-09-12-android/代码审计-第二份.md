同目录「审计与开发建议.md」是另一会话同日独立做的；两份在 A1（断网当成功）和 WebView cookie 上结论一致，这份把 A2–A4 也修了。

## 摘要

代码整体质量高于同规模的独立 App：网络层与判断分离、上传链路的每一步都有「进程在这里死掉」的测试、凭证进 EncryptedSharedPreferences、WebView 关文件访问且外链交系统浏览器、应用内更新逐字节核 sha256。真正的缺陷集中在**边界**：网络异常被折成 status 0 之后没人再看它、几个组件各自维护的生命周期互相打架、续 token 没有互斥。

## 已修（本次，4.6.3）

| # | 文件 | 问题 | 严重度 |
| --- | --- | --- | --- |
| 1 | record/Uploader.kt | `UrlHttp` 把所有异常收成 `HttpResponse(0)`；PUT / complete / stop / finalize 只判 `>= 400`，0 走成功分支，最后 `deleteSession`。飞机模式下停一场录音 = 本地音频没了、深脑那边没收尾。 | 🔴 |
| 2 | record/RecordingService.kt | `drainUntilEmpty()` 传完无条件 `stopSelf()`；全时聆听收第一场也走这条路，服务一死 `onDestroy` 把聆听关了。 | 🔴 |
| 3 | Client.kt | `refresh()` 无锁；界面（`get()`）和上传器（`validAccessToken()`）同时撞 401 各续一次，refresh token 轮换把先到的作废 →「用着用着要重登」。现在单飞：拿到锁先看别人是不是已经续好了。 | 🟠 |
| 4 | Client.kt | 续期请求飞着的时候 `signOut()`，迟到的应答把旧账号凭证写回 store。加登录代际 `epoch`。 | 🟠 |
| 5 | MainActivity.kt | 退出登录不清 `CookieManager` / `WebStorage`，换账号后「网页版」还是上一个人。 | 🟠 |
| 6 | record/UploadWorker.kt, Resume.kt | Worker 只数 SEALED 段；段全传完、stop/finalize 503 时数到 0 就 success，收尾要等用户下次开 App。现在按 DrainResult 判要不要再来。 | 🟠 |
| 7 | AndroidManifest.xml | minSdk 29 但没有旧的 BLUETOOTH / BLUETOOTH_ADMIN（maxSdk 30），Android 10/11 连不上灵魂卡。 | 🟠 |

每一条都有回归测试（UploaderTest ×3、ClientTest ×2、ResumeTest ×5）。②没有单测：要起真服务，模拟器上验：开全时聆听 → 说一段话 → 静 40 秒 → 传完后通知栏应该还是「在听」。

## 建议（没改）

| # | 位置 | 建议 | 类别 |
| --- | --- | --- | --- |
| 1 | record/RecordingService.kt `startPump` | `drainOnce()` 在通知泵的协程里同步跑，一段上传要几分钟时通知栏的计时就停几分钟。把 drain 放到独立协程，泵只管每秒报时。 | 性能 |
| 2 | Client.kt `validAccessToken` | `@Synchronized` 期间发网络请求，别的线程要 token 会一起等（最长 30 秒连接超时）。改成「续期用单独的锁 + 读 token 不加锁」。 | 性能 |
| 3 | MeetingWebScreen.kt | 入场券走 URL 参数 `?t=`，会进 nginx access log。券一分钟死、一次性，风险低；服务端若能改成 POST 表单更干净。 | 安全 |
| 4 | MeetingWebScreen.kt `sameOrigin` | `URI.port` 对 `https://x` 是 -1、对 `https://x:443` 是 443，两者会判成不同源。API_BASE 不带端口时没问题，带了就全部外跳。归一化端口。 | 正确性 |
| 5 | Installer.kt | `cache/apk/` 里每版留一个 apk，不清理；装完（或版本号已经升上去）应删。 | 维护 |
| 6 | record/Vault.kt `FileVault.rename` | `renameTo` 失败只返回 false，上传器不看返回值。同一目录内几乎不会失败，但失败就是「传了却再传一次」。至少打日志。 | 正确性 |
| 7 | HistoryScreen.kt | 本地录音目录按 orgId 钉但没按 userId 隔离；同一手机换账号能看到上一个账号没传完的录音（另一份审计也指出）。产品决定：显示但标明账号，或退出时问一句。 | 安全 |
| 8 | 测试 | 截图门禁（Roborazzi）偶发：HEAD 不动也会红「会议 大字号」（基准本身是半截页）和偶尔「记录 亮色」。根因是 Robolectric 里 IO 协程回主线程那一步偶发丢掉——已排除 AndroidUiDispatcher 队列、Choreographer、Demo 客户端本身；只在某些测试顺序下复现。没追到底；发布门禁走 `testDebugUnitTest` 不受影响。 | 维护 |
| 9 | build.gradle.kts | `isMinifyEnabled = false`：发布包不混淆不裁剪。不是安全问题，但体积能砍一半；开 R8 前要给 org.json / OkHttp / WorkManager 补 keep 规则并回归。 | 维护 |

## 看着好的

- 上传器是纯函数式的（Http / Vault 接口），六步链路的每个中断点都有测试；幂等键、409 各种含义、缺号清单都有注释写清「为什么」。
- 凭证：refresh token 进 EncryptedSharedPreferences，旧明文库迁移后**删除**；access token 只在内存。
- WebView：`allowFileAccess` / `allowContentAccess` / `allowFileAccessFromFileURLs` 全关；同源比较 scheme+host+port 不做前缀匹配；外链交系统浏览器。
- 应用内更新：清单没有 sha256 就不装；流式下载边算 sha；校验不过删包；FileProvider 只暴露 cache/apk 与 cache/diag。
- 服务：`startForeground` 的 ForegroundServiceStartNotAllowedException 接住并说人话；`onTaskRemoved` 故意不 stopSelf 并写明原因。
- 定时聆听诚实：到点是通知，点了才开麦（Android 14 的门），文案说清。
- 文案与节奏有测试守着（CopyGuardTest / RhythmGuardTest）。

**Request Changes → 已改，4.6.3 可发。** 剩下的建议里 1、2、4 值得下一轮顺手做；7 是产品决定；8 是测试基建的债。
