# 010: 深脑 App —— 定位与重做

## 要什么

**先给深脑 App 一条它自己的判据，再谈重写。**

现在这个 App 不满意的四件事——界面、结构、可靠性、定位——只有最后一条是根。
另外三条都是从「不知道该做到哪为止」长出来的：不知道边界，就会在原生里复刻网页；
复刻不完就掺 WebView；掺进来的部分要和原生对齐，于是追像素；屏幕越加越多，
导航就只能靠手工同步两个状态变量。**先定边界，其余三条各自有解。**

而边界在 2026-09-04 变了：**硬件不再是借来的入口，它是深脑的产品和商业模式。**
这一条推翻了《AI 录音设备赛道深度研究报告》9.2 的第一条红线（「不做硬件」），
也推翻了本规格 v2 里「硬件是入口不是产品」那张表。**参照系随之改变**——
App 不再是「网页版在手机上的一个分身」，它是**一件卖出去的硬件的本体验**。

### 结构：导航有两个真源

`MainActivity.kt` 里 `screen: Screen`（9 个变体）和 `tab: Tab`（5 栏）是两个独立的
`remember` 变量，而且不正交：

- 13 处 `tab = Tab.x` 赋值、21 处 `screen = Screen.x` 赋值，4 处必须写在同一行里
  一起改。**漏一处就是一个 bug，而编译器不会说话。**
- `RecordScreen` 被渲染了**两次**：`Screen.Record` 一次，`Screen.Feed` + `Tab.RECORD`
  一次。两处传的参数不一样——前者的 `onOpenHistory` 会 `load()`，后者不会。
  这就是「改一处坏三处」的机器本体。
- `BackHandler` 只能手工枚举组合，每加一个 Screen 就得回来补一条。
- `Tab` 的注释写着「刻意只有四个」，实际是五个。注释和代码已经漂了。

没有 ViewModel：所有状态 `remember` 在 `App()` 这一个 composable 里；`load()` 是它内部
的一个闭包，且只管 `today` 一条数据。其余 21 处是各屏自己直接调 `client.*` 取数——
每一屏有自己的加载态、自己的错误处理、自己的空态判断。

### 界面：颜色守住了，节奏没有

好消息先说：**排除 `Theme.kt`，全项目 0 处硬编码颜色**，121 处走
`MaterialTheme.colorScheme.*`。根上换主题就能全局生效这条设计是成立的。
（`clients/android/README.md` 里写的「43 处」已经过期，实际 121 处——文档腐烂的第一个证据。）

坏消息：纵向节奏是**半执行**。107 处走 `DS.Rhythm`，但仍有 **69 处字面量 dp**，
集中在 `Chrome.kt`(13)、`RecordScreen.kt`(11)、`PageTypes.kt`(11)。
`DS.kt` 里明写「不要再在别处写字面量 dp」，但没有任何东西挡着。

更深一层的问题是**同步方向**：token 的真源是 `packages/ui/src/tokens.ts`，
Kotlin 读不到 TS，于是靠人跟。跟到什么程度看这条提交——
`fix(android): 中性灰阶跟上网页 v2.9——ink-300 从 #9096A4 压到 #898F9D`，
深 7/255，肉眼看不出。**这种跟进不可能长期靠人做对，网页每改一版安卓就掉一次队。**

### 可靠性：9-03 那次事故，补了症状没补根因

事发：账号切错（登录用了另一个邮箱），三份录音笔文件真实同步成功，落进错误账号。
换回正确账号后，本地账本仍说「这三份导过了」，于是「同步全部」永远不会再拉它们——
**而它们在正确账号里一条都没有。**

补法是给 `ImportedRegistry` 的键加了 `orgId` 一维。这个补法是对的。
但根因没补：**这份账用户看不见。**

`clients/mac-recorder` 那套接入手册第 4 步是红线，原话是
「『对方没发』和『我们没接住』长得一模一样」，要求丢弃留痕 + 界面上有收发台账。
安卓这一侧今天：

- `ImportedRegistry` 是 SharedPreferences 里的一堆 boolean，没有界面、导不出、看不到。
- `BleImportService` 跳过一个文件时（设备说没有），只在 `note` 里说一句
  「跳过了一份文件（设备说没有），接着同步剩下的」，跳了哪一份、为什么，没有留下。
- 用户唯一能看到的是「导好了 · XX KB，正在推送到深脑」，然后就断了。
  **推送到深脑之后成没成，App 里没有任何一屏能回答。**

所以这不是「再加一层重试」，是**这一层从来没有可观测面**。

## 定位（本期立的判据）

`clients/android/README.md` 立过两条判据，都很好，但都已被实际演进推翻了，
且没人重写过：

- 「为什么先做安卓不做 iOS」→ 分发。**这条今天仍然成立，保留。**
- 「为什么先做『看』不做『录』」→ 但 v3.1.2 已经在同时做看、录、导，
  `record/` 有 13 个文件。**这条已经失效，本期作废。**

替换成一条。它不再拿网页当参照系，拿硬件当参照系：

> **深脑 App 不是深脑网页的手机版，是深脑硬件的兑现面。**
>
> 硬件卖的是一句承诺——「你说过的话会变成判断」。
> **这句承诺兑现的全过程都发生在 App 里**：从拆开盒子那一刻，
> 到第一次看见「上周那场会，你答应的三件事有一件逾期了」。

这条判据的依据是《AI 录音设备赛道深度研究报告》6.2 收尾那句，一字不改：

> 用户并不是「想再买一支录音笔」，而是「想把说过的每一句话变成可执行、可追溯、
> 可复利的资产」。**硬件只是那张门票**——真正的付费意愿悬在录音之后能不能长出
> 判断与资产。

**门票在硬件，兑现在 App。** 硬件能不能卖第二台、能不能不被退，取决于 App。

由此定边界：

| 层 | App 做到哪 | 判据 |
| --- | --- | --- |
| **兑现** | **第一屏，最高优先级** | 硬件的价值 100% 在这里发生。首屏回答的是「上次那场，长出了什么」，不是「你有 N 条录音」 |
| **开箱** | 全做 | 从拆盒到第一份判断，整条链在 App 里。**这条链决定退货率**，见下节 |
| **采集** | 全做 | 六个入口（灵魂卡 BLE / 手机麦克风 / 系统分享 / 粘贴链接 / 微信文件 / 本地文件），单管道 |
| **落账与交付** | 全做 | 承诺兑现/取消、「能直接发出去的那一页」——路上一步就完的动作 |
| **提醒** | 全做 | 网页做不到：它没法在你不打开它的时候叫你 |
| **信任** | 全做 | 显性录音、告知模板、完整导出、权益只加不减。见「五个退货陷阱」 |
| **读** | 只到「知道有什么、值不值得现在看」 | 再深一律交给 WebView，**并且在界面上承认它是网页** |
| **深度阅读 / 认人 / 逐句转写 / 方法广场** | 不做 | 原生复刻永远追不上，追上了也不值 |

**`MeetingScreen.kt`（318 行）正踩在这条线上**，本期要按上表重新裁。

### 硬件是商业模式之后，App 多出来的四件事

这四件在 v1/v2 里一件都没有——因为那时硬件是别人的。现在硬件是自己的产品，
**它们从「没有也行」变成「没有就退货」**。

1. **开箱到第一份判断（Time to First Value）。**
   硬件的退货窗口是 7 天。用户拆盒 → 配对 → 录第一场 → 导入 → 转写 → 出判断，
   **这条链每一环都在 App 里，卡住任何一环就是一整单退货**。
   现在 `BleScreen` 的形态是一个扫描列表，上面写着「疑似录音笔」——
   那是工程师排查设备时的视角，不是刚拆开盒子的人的视角。
2. **设备管理。** 电量、剩余存储、固件版本、多设备、掉线原因。
   `ble/` 里协议层全都能拿到（`smoke` 巡检项已经在读），但没有一屏在用。
3. **额度与订阅的诚实面。** 硬件带转写额度是这个品类的标配
   （得到 600 分钟/月、钉钉 A1 1000 分钟、安克 1200 分钟）。
   额度显示在 App 里，**它是商业模式的落地面，也是差评的第一来源**（见下节）。
4. **激活与绑定。** 硬件卖出去之后怎么绑到账号、换人用怎么办、
   9-03 那次「账号切错」的事故在硬件卖出去之后会变成常态而不是意外。

### 五个退货陷阱（赛道报告 6.2，逐条转成 App 的约束）

赛道报告列了五条退货与差评驱动因素。它们全部是 App 层能防住的，
所以逐条转成本规格的硬约束：

| 差评驱动 | 报告里的原话 | App 的约束 |
| --- | --- | --- |
| **额度焦虑** | 免费 300–600 分钟「勉强够一半」；**得到「先免费后砍权益」直接触发差评潮** | 不做倒计时式焦虑条；按分析次数/席位计，不按分钟计（价值洞察 6.2 第四条）。**权益只能加不能减，写成红线** |
| **白牌伤参数** | 199 元卡实测拾音 1–1.5 米、多人「糊成一团」、参数乱标 | 界面不吹任何参数与准确率。**反过来做诚实反馈**：这场录音是否有人声重叠、是否离得太远 |
| **停服恐惧** | 搜狗录音笔停服让「终身免费」破产；Limitless 卖身后数据限期导出——**用户意识到买的是一张服务年票** | **完整导出必须能在 App 里一键完成**（音频 + 转写 + 判断）。**并且这条要提到硬件页当卖点**（邱 2026-09-04 定）——得到把「终身免费使用」印成头号标签、Plaud「发现」页第一项是私有云同步，两家都在正面回应这个恐惧；对卖判断资产的深脑更该讲。埋在「我的」里等于没说 |
| **隐私红线** | 欧盟 CJEU C-422/24 要求即时告知；**「正面摆放 + 口头告知反而成了专业形象」** | 显性录音 + 告知模板（已在「上游硬约束 2」）。**这不是合规成本，是硬件形态自带的卖点**：卡放桌子中间 + 说一句，比偷偷录显得专业 |
| **同质化疲劳** | 「一半人骂智商税，一半人用了回不去」 | 首屏必须在**第一周之内**让人看到一次「这东西替我记住了我自己忘了的事」。这是本规格「兑现」排第一的原因 |

### 采集面：双入口，单管道（邱 2026-09-04 定）

原来「待解决 1」问的是「『录』这一条到底留不留」。**答案是留，而且专用硬件与手机
麦克风两个入口都要**——对标得到：得到大脑（App 录）+ GET Seed 录音卡（699 元，
磁吸卡 3.1mm，每月 600 分钟免费转写），两个入口一个后端。

这不是骑墙。**骑墙的定义是两套代码，不是两个入口。**
`ble/Ingest.kt` 已经把这件事做对了，原话：

> 把从录音笔导进来的一个文件，交给**和手机录音同一条上传链路**。另写一条就是把
> 这些坑再踩一遍——而且两条路会慢慢长歪，某天只有一条修好了另一条没有。

**这条注释升格为本规格的架构约束**：所有采集入口——录音笔 BLE、手机麦克风、
系统分享进来的第三方文件——都必须汇进 `record/` 那一条上传管道。
**新增入口只准新增「源」，不准新增「管道」。**

本期三个入口的分工（后三个排下一期）：

| 入口 | 用户 | 状态 |
| --- | --- | --- |
| **灵魂卡**（CB08 BLE 导入） | 高频、重度、要长续航 | 已做完，`ble/` 12 个文件。**可多台** |
| 手机麦克风 | 零门槛、临时起意、第一次用 | 已有 `record/`，后台存活未验证 |
| **系统分享（第三方导出的音视频/文字）** | **已经在用别家硬件、不愿换设备的人** | **完全没有。见下** |

第三个入口是上游文档里的 **A3，优先级 P0（入口）**，原话「用户已在用硬件与转写
工具，不愿换设备」。安卓端接它的成本很低——注册 `ACTION_SEND` / `ACTION_SEND_MULTIPLE`
的 intent-filter，收到就走同一条 `Ingest`。**收益是把飞书妙记、通义听悟、讯飞、
钉钉、Plaud、GetSeed 的所有用户变成潜在用户。**

### 「不做硬件」这条红线作废（邱 2026-09-04）

上游《AI 录音设备赛道深度研究报告》9.2 立的三条红线第一条是「不做硬件」，
9.1 表格写「① 采集（硬件）｜无硬件｜不做。把全行业硬件当成传感器网络借力」。

**这一条取消。** 理由：硬件已经成为 AI 的入口，并且是一个成立的产品化商业模式。
报告写于「白牌 199 元与钉钉/飞书双重挤压」的判断之下，而 2026-08 的在售格局
（得到 GetSeed 699 / 钉钉 A1 499–1299 / 安克录音豆 899 / 讯飞录音卡 999 /
TicNote 999–1499 / Plaud 1149–1299）说明这个价格带是分层成立的，不是被打穿的。

**红线 2、3 仍然有效**：不做转写、不做通用纪要；不做「客气版总结」。

作废这条红线之后，剩下的判据只有一条，它约束的不是做不做，是做成什么：

> **硬件是门票，App 是兑现。**
> 硬件不靠参数赢，靠它后面那一层赢——这正是报告核心判断一说的
> 「录音硬件是 AI 的感官，不是 AI 的产品，它的价值取决于上一层的分析能力有多强」。

### 采集面永不排他

即使硬件成了自己的产品，**第三个入口（系统分享）仍然必须做**，理由变了但更硬：

- 上游 A3 是 P0（入口）：「用户已在用硬件与转写工具，**不愿换设备**」；
- 排他会把深脑锁死在自家硬件的销量上，而判断层的天花板应该比硬件高一个量级；
- 报告 9.3 线路 A 明写「入口是别人的，判断是自己的——这是可以长期借力的杠杆位」。

**判据：一个只用手机、或者只用别家录音笔的人，必须能完整用深脑。**
自家硬件带来的应该是更好的体验（免配置、带额度、长续航），不是唯一的入口。

## 信息密度：一屏只让人做一个决定（邱 2026-09-04 定）

「信息量不能太大」是本期的一条硬约束，不是审美偏好。理由在上游已经写过两遍：
《用户价值洞察》缺口 5 说手机是「一扫而过的场景」，`Api.kt` 说
「**一条猜想会被当成事实**」——**密度失控在这个产品里不是难看，是危险**。

三条规则，可测：

1. **每个区块默认只露最要紧的一条，其余收成一行「还有 N 条 ›」。**
   「今天」有四个区块（承诺 / 洞察 / 预测 / 待认人），四个全展开就是一堵墙。
   数字仍然给全——用户要知道有多少，但不必一次读完。
2. **猜想（`conjecture`）默认折叠。**
   它信息量最大、最需要上下文、也最容易被当成事实。折叠态只给一行标题＋
   「深脑的猜想 · 点开看它凭什么」。**亲证与推断照常展开**——这两档有原话托底。
3. **一屏只让人做一个决定。**
   出现两个并列主按钮就是超载的信号。次要动作降级为文字链或收进「···」。

**验收**：任意一屏在 360×780 的首屏内，需要用户读的正文不超过 5 条；
超过就要折叠。这条要在设计走查里逐屏过，不靠自觉。

## 上游文档带来的硬约束

以下四条来自《深脑用户价值洞察》与《AI 录音设备赛道研究报告》，是产品级判据，
不是界面偏好。它们约束安卓端能做什么、不能做什么。

1. **不做会中打扰。**（缺口 5「在场权」+ 6.2 第一条）
   不做实时插话、弹窗提示、副驾驶形态。原声：「你在写别人刚说的话时，
   就错过了正在说的话」。产品宪章级的原则是**「会中不需要看任何屏幕」**。
   → 录音界面的目标是**按下之后可以把手机扣过去**，不是把转写滚给人看。
   → 这也顺带解释了为什么走事后批处理是对的：不是技术妥协，是产品立场。

2. **录音状态必须显性化，且提供告知模板。**（A8，P1）
   原声：「把卡放桌子中间说一句我录个音，既是合规也是专业」。
   → 录音中要有**在锁屏和通知栏都看得见**的状态；
   → 要有一句可以直接念出来的告知文案，放在开录那一屏；
   → **明确不做隐形偷录**——6.2 第三条把「隐形录音卖点」列为品牌污染。

3. **价值排序决定屏幕排序。**（价值洞察 十）
   > 承诺账本 > 可交付的那一页 > 判断可验证化 > 证据链 > 洞察深度 > 员工自证

   → 「今天」做到期承诺，排第一位，**这个选择是对的，保留**；
   → 排第二的「**能直接发出去的那一页**」（A4：决议 / 负责人 / 时间 / 待确认，
     可导出可分享）**安卓端今天完全没有**。手机上分享比网页顺手，这是手机该拿的活。

   转写已经水电化，全员 95–98%。安卓端界面上**不出现准确率数字**，
   也不做模板数量竞赛。

## 不做什么

### 灵魂卡的权益（本规格拍板，2026-09-04）

原问题是「带不带转写额度、多少」。**答案是：不带转写额度，因为深脑根本不按分钟计量。**

《深脑产品机会地图》6.1 已经把这件事判死了：分钟制订阅是最差的定价，
「一段 40 分钟的投决讨论可能值 5000 元判断费，一天的课程录音只值零花钱」。
6.2 的免费层写的也是「**导入不限** + 每月 3 次带证据判断」。
所以计量单位从一开始就该是**判断次数**，不是音频长度。

| | 转写 / 导入 | 快判断（单方法） | 深判断（多方法 + 跨录音） |
| --- | --- | --- | --- |
| 推理成本 | 已水电化 | 1× | **5–20×**（6.3） |
| 免费 / 无卡 | 不限 | 每月 3 次 | 0 |
| **买了灵魂卡** | **不限** | **不限** | **每月 10 次，永久** |
| Pro ￥99/月 | 不限 | 不限 | 不限（软上限） |

四条理由：

1. **「转写不限」要写死，并且当卖点讲。**全行业都在这里制造焦虑
   （得到 600 分钟/月、钉钉 A1 1000、安克 1200、超出约 0.3 元/分钟），
   而转写已经水电化、成本可控。**「你录多久都行」是最便宜的差异化**。
2. **随卡赠的是深判断，不是快判断。**快判断成本低，直接不限；
   深判断成本 5–20×，6.3 要求把它做成「有价感的稀缺动作，而不是免费无限」。
   「稀缺但每月都有」正好是续费与复购的钩子。
3. **「永久」两个字是这套权益的全部重量。**得到「先免费后砍权益」引爆差评潮，
   是所有额度型定价的必然结局。硬件是买断，买断带来的权益就必须是终身的——
   **这也是硬件价格锚立得住的唯一理由**：你买的不是一张卡，是一份永久的月度深判断额度。
4. **多台可叠加。**两张卡＝每月 20 次深判断。硬件本身有成本，叠加是诚实的，
   也让 S2 的「再买一支」有了真实理由，而不是一句推销。

**存储一并定了：原始音频保留 12 个月（Pro 永久），转写与判断永久。**
不承诺「无限存储」——那是一条一定会被砍的权益，而深脑的资产本来就是判断不是音频。
12 个月覆盖绝大多数回溯需求，且是一个不会往回改的承诺。

### 定价与 Pro 的边界（邱 2026-09-04 定价 899）

**灵魂卡 899 元。**落在 499 那条线之上，所以「每张每月 10 次深判断」不用下调。
价位坐标：安克录音豆 899（同价）· 钉钉 A1 799 · 得到 GetSeed 699 · 讯飞 999 · TicNote 999。
**中位偏上，这一档要求开箱有仪式感，但不必奢侈**——S1/S2 两屏按这个标准做。

899 带出一个必须同时定的问题：**买断的永久权益会不会把 Pro 订阅吃掉。**
如果 10 次/月够用，用户就永远不买 ￥99/月。所以两者卖的东西要分开：

| | 灵魂卡 899（买断，永久） | Pro ￥99/月 |
| --- | --- | --- |
| 采集 / 转写 / 导入 | 不限 | 不限 |
| 快判断 | 不限 | 不限 |
| 深判断 | **10 次 / 张 / 月**，多张叠加 | **不限** |
| 承诺账本 · 人的兑现率 · 预测记账 | **全开** | 全开 |
| 判断力季报 · 优先分析队列 | — | **有** |

**判据：卡卖「单场深度」，Pro 卖「长期复利」。**
承诺账本、人的兑现率、预测记账**一律不锁**——它们是深脑的立身之本和最强口碑资产，
锁起来等于把差异化藏起来。Pro 加的是次数不限与周期性产物（季报）。

> 这张表里只有「899」是邱定的，Pro 的边界是我据此推的，**需要点头**。

**推翻这套方案的条件**（写在这里，免得以后当成信仰）：
- 若深判断的真实边际成本低到 10 次/月不构成任何压力 → 直接改成不限，只留 Pro 卖跨录音与记账本；
- 若灵魂卡定价压到 499 以下 → 10 次/月要下调，否则硬件毛利被判断成本吃穿；
- 若实测发现用户一个月用不满 3 次深判断 → 问题不在额度，在「值得做深判断的场合太少」，
  那要改的是方法引擎的触发时机，不是数字。

### 多设备（邱 2026-09-04 定）

「一人可以多台，不同设备的入口都是可以的」——这句话有两层，两层都要实现：

1. **多台灵魂卡。**`ImportedRegistry` 已经按 `orgId|deviceAddress|fileBase` 三维记账，
   多台在协议层天然成立。要补的是界面：设备是**列表**不是单卡，每台可自己命名
   （「随身那张」「办公室那张」），台账可按设备筛。
2. **灵魂卡之外的入口一律平等。**手机麦克风、系统分享、别家硬件导出的文件，
   在「记录」的分段里与灵魂卡并列，**不做主次视觉差**。
   这是「采集面永不排他」在像素上的兑现——一个只用手机的人，界面上不该处处看见
   「你还没有灵魂卡」。

2. **WebView 那几页的登录态桥要不要统一？**
   `MeScreen` 和 `MeetingWebScreen` 各有一套开法。要么合成一个带登录态的
   `WebPage(path, title, back)`，要么明确它们是两件事。现在是「凑巧都能用」。

3. **token 跨端同步要不要上生成器？**
   `packages/ui/src/tokens.ts` → `Theme.kt` 现在靠人跟。要么写个生成脚本进 CI，
   要么接受「安卓的色值会长期落后于网页」并在文档里说出来。
   **两个都行，唯独不能是现在这样——嘴上说同步，实际靠某次提交想起来。**

## 实现约束

- **导航一个真源。** `screen` 与 `tab` 合并成一个可穷举的状态；每个屏幕在整棵树里
  **只出现一次**。合并方式（Navigation Compose / 自己写一个 sealed 状态机）不限，
  但「同一个屏幕在两处渲染且参数不同」这件事要被测试挡住。
- **状态出 composable。** 每屏一个持有者（ViewModel 或等价物），`load()` 不再是
  `App()` 里的闭包。判据：屏幕的加载/错误/空态**在 JVM 上能测**，不用装到手机上。
- **数据一条路。** 21 处屏幕内直调 `client.*` 收进一层，让「401 怎么办」「离线拿缓存」
  这类判断只有一个地方写。`Api.kt` 零安卓依赖这条继续保持——它是对的。
- **台账是一等公民，不是调试功能。** 见下一节。
- **间距零字面量。** 69 处字面量 dp 清零，并且**加一条测试钉住**——
  `DS.kt` 里的那句「不要再在别处写字面量 dp」没有执行力，一句注释挡不住任何人。
- **文档里的数字不许手打。** 本文里所有计数（8,574 / 121 / 69 / 57）都是当天数出来的，
  半年后必然是假的。要么让脚本生成，要么在旁边标日期——就像现在这样。
  `README.md` 里那个「43 处」已经是活例子了。

### 台账要长什么样

一屏，能回答四个问题，缺一个都不算做到：

1. **这支笔上有什么？** 设备文件列表 + 每份的状态（未导 / 导入中 / 已导 / 跳过）。
2. **跳过的为什么跳过？** 判据要写出来：「本账号已导过」「设备说没有这个文件」
   「文件坏了」。只写「跳过」等于没写——它和「设备没这份」在界面上长得一样。
3. **导进去之后到哪了？** 本地已落盘 → 上传中（第几片）→ 深脑已收。
   现在这条链在「正在推送到深脑」之后就断了。
4. **这份台账看不到什么？** 明写：换过账号之前的记录不在这里；本期之前导的不在这里。
   **不写这一句，用户会把「台账里没有」读成「没导过」，那就是 9-03 那次事故再来一遍。**
