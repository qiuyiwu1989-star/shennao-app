# 011 · 手机录音在后台活下来

> 2026-09-05。状态：**代码已做能做的部分，真机矩阵一台没跑。**

## 为什么单独立一条

「会中不看屏幕」是 010 的第一原则。手机录音这条入口，锁屏之后活不活得下来，
决定了它是「能用」还是「演示用」。而这件事**在模拟器和 JVM 上完全测不出来**——
只有各家 ROM 的真机才知道答案。

## 已经做了的（3.5.0）

| 层 | 做法 | 依据 |
| --- | --- | --- |
| 前台服务 | `RecordingService` 是 `foregroundServiceType="microphone"` 的前台服务，常驻通知 | 早就有 |
| 被杀后自愈 | 开新一场前先 `recoverOrphans()`：上次被杀留下的半截录音补封、照传 | 早就有，`RecordingService` ACTION_START |
| 麦克风被抢 | `RecordState.GAVE_UP` 有话说：「已录到的部分正在推送」 | 早就有 |
| 系统电池优化豁免 | `KeepAlive.isExempt` 查、`requestIntent` 申请；「我的」页一张卡，回到前台会重查 | 标准 API |
| 厂商自启动开关 | `KeepAlive.romHint(manufacturer)` 给六家的路径；认不出的厂商**不编** | 没有 API，只能指路 |

原则：**只说查到的事实。** 豁免与否查得到就直说；厂商开关查不到，就只给路径，不说「已设置」。

## 没做、也不打算做的

- 不做「保活黑科技」（双进程守护、1 像素 Activity、播放无声音频）。这些在新系统上被逐个封杀，
  且违反 Play 政策；靠它们活下来的录音，换一次系统更新就死。
- 不做自动跳厂商设置页。各家 intent 年年变，跳错了是空白页，比不跳更糟。
